## 2026-11-26 架构变更（正文已同步，非待办）

**Lambda 拆分：6 个按域合并 → 一条路由一个函数（37 个接口函数 + 1 个维护函数）。**

- 原因：单职责、低耦合；改一个接口只发布一个函数，一条路由出错不牵连其他接口。
- 代价：38 个函数、38 个别名与日志组；每条路由首次访问各有一次冷启动（100 人规模可接受）。
- 落点：契约 §2.6（逐条映射）、架构 §5.0.1 / §10.4、方案 12.1 / 12.3、infra `modules/apigw` 路由表与 IAM/可观测清单、新人文档 02 §1.2。
- 门禁：`verify_routes_structure.sh`（37 条路由 ↔ 37 个函数、无复用）+ `verify_lambda_inventory.sh`（四处清单一致）。

## 方案设计 v1.13.7 文首修订说明（原文搬迁）

**v1.13.7 修订说明**：**改掉一个设计错误——图片不再有独立可见性，完全跟随所属笔记**。原设计（v1.13.4 及以前）里「笔记私有 + 图片公开」会让正文受保护而附件仍全网可读，「笔记公开 + 图片私有」又会让公开页裂图；两套可见性真源必然互相矛盾。本版定稿：①笔记新增 `visibility` 档位（`private` 默认 / `public` 持链接匿名可读）；②图片物理前缀由「引用它的笔记中最宽的可见性」派生（公开优先），不再逐张设置；③笔记切换可见性走 `POST /notes/{note_id}/visibility`（202 + `visibility_migrate` job，迁移图片前缀并改写引用）；④团队开关改为「默认笔记可见性 + 强制私有」，强制私有在**设置笔记为公开时**拦截（400 `NOTE_VISIBILITY_FORBIDDEN`），原 `ASSET_VISIBILITY_FORCED` 与 presign 侧的可见性参数一并删除。影响 6.2 / 6.3 字段、8.1–8.4、12.1、17.5；三档成本 $0.61 / $1.38 / $2.67 不变（图片仍走既有 CDN 前缀与预签名，无新增资源）。

**v1.13.5 修订说明**：依据《线框规格 v0.1》的 TODO 收口，补两处口径（均为产品侧定稿，不动架构、不动成本）：

- **P-A（7.4 写边界自相矛盾）**：7.4 原写「在共享目录内新建的笔记/子目录自动继承当前目录权限」，但同节 v1.13.3 K3 的六处写白名单明确禁止 `edit` 写 `.dir_meta.json`——建子目录必然要写它，两句话互斥。定稿：**`edit` 可在共享目录内新建/编辑笔记，不能新建子目录**；子目录只有 owner 能建。理由：结构归 owner，避免 100 人内部工具里被共享者把别人的目录树改乱，事后清理成本高于收益。
